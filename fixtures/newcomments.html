chimpontherun 1 minute ago | parent | context | on: Locating the source of a mysterious beep

I did in manually, i.e., visually. By looking at the phase shift and moving in direction of the channel that heard the beep first.

The beep frequency is about 3000-3500 Hz, which makes its wavelength about 10cm (1/3 of a foot). The piezo speaker in the smoke detector is so small that it takes 3-4 wave periods to go from silent to full blast. Meaning, if my stick was pointing perfectly to the source (it never was, obviously, but if), then one of the "mics" would hear the sound at full blast while the other still wouldn't hear anything.

So, I would have Audacity recording, hear the beep, stop the recording and zoom at the wavefront of the beep. Whichever mic shows the signal first, I'd move my stick (and the laptop) in that direction. After 2 or 3 moves and I was right under the source. Took me about 2 or 3 beeps at different stick orientation to understand that the sound is coming from above.

Slartie 2 minutes ago | parent | context | on: AI usage generates a fragile codebase

Code has an invisible attribute "confidence" associated with it. All code has it. So-called "battle-tested" code bases have a high value, newly-written stuff starts at low values, and the only two ways of increasing it are 1) rigorous testing and 2) actual usage in production scenarios at scale.

AI can generate "confidence" only in very limited amounts. It can help with testing, but that becomes very expensive and hard once we leave the realm of tests that can be simply written with code, like unit tests. At some point, the only way to increase the confidence in a codebase is actual testing with actual, real user interaction. And once that's maxed out, the only way to further generate more confidence is to get it into production and let real users (not test users, production users) find the remaining bugs no tester and no AI ever managed to hit.

This is the sole reason why AI doesn't make code "disposable" - yes, it can rewrite any code base far more quickly than any human, but that new code will start at low confidence values - AI cannot transfer the confidence that the old codebase achieved simply due to being smashed against reality in production use to the new code it writes.
